# کلینیک هوشمند — دستیار پیش‌غربالگری و ویزیت آنلاین (نسخه آزمایشی)

ایجنت هوش مصنوعی که بیمار را بر اساس پزشک انتخابی‌اش بررسی می‌کند، علائم خطر را شناسایی می‌کند و برای پزشک **پیش‌نویس** می‌سازد. فقط پزشک تأیید می‌کند و بعد از تأیید **کد** صادر می‌شود و **گفتگو** با پزشک باز می‌شود.

> پروژه‌ی آموزشی است. پزشکان، بیوگرافی‌ها، نظرات بیماران و داده‌های دارویی **نمونه و فرضی** هستند.

## اجرا (ویندوز)

۱. zip را **Extract All** کنید. ۲. روی `start.bat` دوبار کلیک کنید (مرورگر خودش باز می‌شود).

یا با ترمینال داخل پوشه: `python server.py` و سپس http://127.0.0.1:8000

فقط پایتون ۳ لازم است؛ هیچ پکیجی نصب نمی‌شود.

برای گذاشتن روی اینترنت (GitHub + Render) فایل `DEPLOY.md` را ببینید.

## پزشکان و رمزهای دمو

| پزشک | تخصص | خروجی ایجنت | رمز |
|---|---|---|---|
| دکتر سهرابی (مرد) | پزشک عمومی | پیش‌نویس نسخه‌ی دارویی ← **کد نسخه** برای داروخانه | 1111 |
| دکتر مرادی (مرد) | فیزیوتراپیست | برنامه‌ی تمرینی (بدون دارو) ← **کد پذیرش** | 2222 |
| دکتر موسوی (زن) | دندان‌پزشک | خلاصه‌ی پرونده + اولویت ← **کد پذیرش** | 3333 |
| دکتر کرامتی (زن) | زنان و زایمان | خلاصه‌ی پرونده + اولویت ← **کد پذیرش** | 4444 |

هر پزشک فقط پرونده‌های خودش را می‌بیند.

## پنل مدیر

تب «مدیر» (رمز دمو: 9999، روی Render با متغیر `ADMIN_PIN`) همه‌ی فرم‌های پرشده‌ی همه‌ی پزشکان را با عکس‌ها و گفتگو نشان می‌دهد و امکان دانلود JSON دارد.

## مسیر بیمار

لیست پزشکان ← پروفایل (بیوگرافی، تخصص‌ها، نظرات نمونه) ← «ورود به بخش ویزیت» ← فرم اختصاصی همان پزشک (سؤال، رنگ و استایل متفاوت) ← شرح حال ← **ارسال عکس** (تا ۳ عکس، مثلاً عکس دندان‌ها) ← بررسی ایجنت ← تأیید پزشک ← کد + گفتگو.

- ایجنت **پیشنهاد هدایت** هم می‌دهد (مثلاً بیمار باردار نزد پزشک عمومی ← «دکتر کرامتی مناسب‌تر است»؛ دندان‌درد ← دندان‌پزشک؛ کمردرد ← فیزیوتراپی).
- تصاویر را **فقط پزشک مربوطه** می‌بیند. ایجنت تصویر را تحلیل نمی‌کند (ایده‌ی توسعه: مدل بینایی).
- نمونه‌های سریع روی هر فرم برای دمو هست.

## حالت‌های ایجنت

| حالت | شرایط | رفتار |
|---|---|---|
| `demo` | پیش‌فرض (بدون کلید) | گردش‌کار ثابت؛ بدون اینترنت |
| `llm` | متغیر `ANTHROPIC_API_KEY` | خود Claude تصمیم می‌گیرد کدام ابزار را صدا بزند |

در حالت `llm` اگر خطایی رخ دهد، امن به `demo` برمی‌گردد. اجبار حالت دمو: `AGENT_MODE=demo`.

## نوبت‌دهی واقعی (وقت ایران، تاریخ شمسی)

وقتی ایجنت بیمار را برای **ویزیت حضوری** ارجاع می‌دهد (یا پزشک پرونده را می‌پذیرد/دندان‌پزشک و زنان تأیید می‌کنند)، سیستم از روی **ساعت واقعی سرور (UTC+03:30)** و برنامه‌ی کاری همان پزشک، اولین وقت خالی را می‌دهد؛ مثلاً «شنبه ۲۳ آبان ۱۴۰۵ ساعت ۱۶:۰۰». جمعه و ساعت‌های گذشته داده نمی‌شود، حداقل ۳۰ دقیقه فاصله از «الان» رعایت می‌شود، دو بیمار یک وقت نمی‌گیرند و بیمار تا ۳ بار می‌تواند «وقت بعدی» را بزند. برنامه‌ی هر پزشک در `data/doctors.json` (فیلد `schedule`) است.

## دستیار پزشکی (تب «دستیار پزشکی»)

پرسش و پاسخ آزاد با Claude درباره‌ی دارو و بیماری (اطلاعات عمومی، محدود به فهرست نمونه نیست). نیازمند `ANTHROPIC_API_KEY` است؛ بدون آن تب پیام «غیرفعال» نشان می‌دهد. گاردها: تشخیص و دوز شخصی نمی‌دهد؛ اگر پیام علامت خطر داشته باشد، بدون صدا زدن مدل، هشدار ثابت ۱۱۵ برمی‌گردد؛ سقف `RATE_ASSIST` (پیش‌فرض ۳۰ سؤال در ساعت برای هر IP)؛ مدیر همه‌ی پرسش‌ها را در تب «مدیر» می‌بیند. هر سؤال هزینه‌ی API دارد.

> این دستیار با ایجنت نسخه‌نویس جداست: تجویز دارو فقط از مسیر پزشک و با فهرست محدود و کنترل‌شده انجام می‌شود.

## معماری

```
بیمار ─► انتخاب پزشک ─► فرم اختصاصی (+عکس) ─► ایجنت ─► پیش‌نویس ─► پزشک (تأیید) ─► کد ─► گفتگو / داروخانه
ایجنت:  check_red_flags → suggest_doctor → check_risk_factors →
        GP: search_guidelines → check_drug_safety → create_draft_prescription
        فیزیو: search_physio_plan     دندان/زنان: prepare_visit_summary     (یا refer_to_doctor)
```

| فایل | نقش |
|---|---|
| `agent.py` | ایجنت (حالت دمو + حلقه LLM) |
| `tools.py` | ابزارها و **گاردهای ایمنی** |
| `server.py` | API، احراز هویت پزشکان، گفتگو، تصاویر، داروخانه |
| `index.html` | رابط بیمار / پزشک / داروخانه |
| `data/doctors.json` | پزشکان، بیوگرافی، نظرات، فرم‌ها |
| `data/*.json` | علائم خطر، راهنمای درمانی، دارو، برنامه‌های فیزیوتراپی |
| `images/` | (اختیاری) عکس واقعی پزشکان؛ راهنما داخل پوشه |
| `tests.py` | ارزیابی |

## نکات طراحی (برای ارائه)

1. **ایجنت فقط پیشنهاد می‌دهد، پزشک تصمیم می‌گیرد.** ایجنت ابزاری برای صدور کد ندارد.
2. **گاردهای ایمنی در کد هستند، نه فقط در پرامپت.** مثلاً فقط پزشک عمومی نسخه‌ی دارویی می‌گیرد؛ با علامت خطر، هیچ خروجی دارویی ساخته نمی‌شود؛ داروی ناایمن (آلرژی، تداخل) رد می‌شود.
3. **تخصص‌محور:** هر پزشک فرم، خروجی و قواعد خودش را دارد (فیزیو بدون دارو، زنان و دندان با خلاصه و اولویت).
4. **گفتگوی ایمن:** فقط بعد از تأیید باز می‌شود؛ اگر بیمار علامت خطر بنویسد هشدار می‌گیرد و پزشک هم می‌بیند.
5. **شفافیت:** مراحل تصمیم‌گیری ایجنت (ورودی/خروجی ابزارها) در رابط قابل مشاهده است.
6. **حریم خصوصی تصاویر:** فقط فرمت JPG/PNG/WEBP با بررسی محتوای واقعی فایل، حداکثر ۳ عکس، قابل مشاهده فقط برای پزشک همان پرونده.

## ارزیابی

```bash
python3 tests.py
```

۴۰ سناریوی بالینی (چهار پزشک)، تست تقویم شمسی و نوبت‌دهی (با ساعت ثابت)، دستیار پزشکی (با مدل جعلی)، تست‌های گارد در برابر مدل اشتباه‌کار، تست حلقه LLM با مدل جعلی، و تست‌های کامل جریان HTTP (احراز هویت هر پزشک، گفتگو، تصاویر، کد نسخه/پذیرش، داروخانه). همه موفق‌اند.

## محدودیت‌ها (صادقانه)

- حالت `demo` علائم را با **کلیدواژه** تطبیق می‌دهد (نفی ساده مثل «تب ندارم» را می‌فهمد). حالت `llm` این ضعف را پوشش می‌دهد.
- حالت `llm` و دستیار پزشکی با API واقعی تست نشده (فقط با مدل جعلی)؛ قبل از ارائه با کلید خودتان یک بار امتحان کنید.
- پایگاه دارو و راهنماها نمونه‌اند؛ در نسخه‌ی کامل باید با منابع معتبر (RAG) جایگزین شوند.
- نظرات و بیوگرافی‌ها فرضی‌اند و با برچسب «نمونه» نمایش داده می‌شوند. در سامانه‌ی واقعی نظرات باید از بیماران واقعی باشد.
- داروخانه شبیه‌سازی است. ذخیره‌سازی فایل JSON است و رمز پزشکان ثابت (فقط دمو). گفتگو و عکس‌ها رمزنگاری نمی‌شوند.

## ایده‌های توسعه

RAG روی راهنماهای بالینی، تحلیل عکس با مدل بینایی (با نظارت پزشک)، حافظه‌ی بلندمدت بیمار، دوز بر اساس وزن، پیامک یادآوری نوبت، نسخه‌ی الکترونیک واقعی و احراز هویت قوی.
